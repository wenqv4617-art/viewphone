### 2.1 但与 OKLCH 标准冲突（重要）

| 项 | 提示词标准 | 用户给的 hex 实测 | 结论 |
| :--- | :--- | :--- | :--- |
| 底块明度 L | 92~94% | **93.8~95.6%** | 偏亮 1.6~1.8 个点 |
| 底块彩度 C | 0.05~0.07 | **0.006~0.024** | **只有标准的 1/3 左右** |
| 字色明度 L | 38~45% | **42.7~50.3%** | 一半以上偏亮 |
| 字色彩度 C | 0.10~0.12 | **0.027~0.139** | 两极分化 |

**为什么我没有擅自改成"标准值"**：我按标准区间（底 L93.5/C0.06、字 L40/C0.11）重算过一版，
结果**部分色相在 sRGB 里根本达不到 C=0.05~0.07**（蓝 248° 最高约 0.036、紫 250° 约 0.036、
砖红 57° 约 0.048）；强行拉满彩度会让这些色块明显变艳、失去"不刺眼"。
命令与完整数据：`node design/samples/_tools/check-color.mjs`、`node design/samples/_tools/fix-color.mjs`。

**⇒ 需要你裁决（见汇报的决策点 1）**。
