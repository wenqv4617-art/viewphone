### 一句话定位
> 一台**装满了 AI 角色的平行手机**：拟真桌面上住着多个角色，能像微信一样聊天、进群、发朋友圈、打语音、送红包；角色有自己的日程、穿着、位置、心情与长期记忆，会主动找你、会有自己的生活。
> **核心（60% 以上工程量）是与角色的高质量长周期对话**；其余应用是围绕核心的「世界感增强层」，允许分期交付。

### 为什么必须原生（不可动摇）
WebView 方案在物理上做不到三件事，而这三件事恰好是产品护城河：
1. **离开 App 也能收到、也能回**——WebView 会被系统冷冻/回收，关键路径不能依赖它。
2. **提示词编译只有一个实现**——若前台在 WebView、后台在原生，则必然有两份拼装逻辑，最终分叉成两套互相矛盾的提示词（前身项目作者的血泪结论）。
3. **十万条消息不卡**——DOM 节点爆炸是 WebView 的固有代价。

> 前身教训：旧项目作者在开发日志里写下「不试图『让网页别被冻结』，而是**承认它随时会死**」与「原生不可能复刻 `buildSystemPrompt()` 那一整套…**硬复刻必然和网页版慢慢分叉**」。这两句话就是本项目形态的由来。

## 一、第一条宪法：数据永不因体积而崩溃

这是本项目**第一目标**，高于功能数量、高于开发速度、高于任何性能优化。

1. **二进制永不入库。** 图片、语音、视频、导入的书籍正文、桌宠素材、立绘、生成图——**一律以物理文件存放在独立存储层**，数据库只存相对路径或 `media://` 引用。
   > 前身事故：生图结果把缩略图与原图**双份 base64 写进同一条消息**，导出 JSON 膨胀到 40MB，单次跨进程传输直接崩溃。
2. **写入路径必须有真实守卫。** 任何把 `data:` / base64 / 大 `ByteArray` 写进持久化层的调用，必须在**真实仓储调用点**被拦截并抛错；守卫必须挂在会被执行的代码路径上，并配 CI 负向测试。
   > 前身事故：前身新工程里写了守卫函数却「只有测试引用它」，仓储层不存在 → 承诺等于没做。
3. **列表查询永不"全量拉到内存再过滤"。** 所有列表必须走**复合索引 + 游标分页**；禁止 `OFFSET` 深翻；禁止为绕开 schema 问题而放弃索引。
   > 前身事故：为规避一次 `SchemaError`，作者把「不改 schema、`toArray()` 全量拉内存再 `filter()`」**立成了规范**，腐化被制度化。
4. **索引只建在会被查询与排序的字段上。** 大文本字段（消息正文、章节正文、图片 URL）**永远不进索引**。
   > 前身事故：87 张表里 11 个大文本字段被列入索引，索引体积膨胀。
5. **容量必须可见，失败必须可见。** 存储超限、写入失败、配额不足一律**向用户显式报错**；禁止 `try/catch` 只写日志。
   > 前身事故：`QuotaExceededError` 被静默吞掉，用户以为保存成功（"照片保存了却没有"）。
6. **备份必须完整且由 schema 驱动。** 备份/清空/导出/导入的表清单**从表注册表派生**，任何未注册的表 = CI 失败；导入必须校验版本与校验和。
   > 前身事故：备份只覆盖 43/87 张表，快穿局、奇遇、衣柜、桌面照片**从未被导出过**，换机即永久丢失；新增一张表要手抄四处，漏一处导致事务死锁。
7. **备份/导出必须流式。** 禁止把整库 `serialize` 成一个大字符串；必须分块流式写盘，单次跨层传输有明确上限。

## 二、第二条宪法：单一事实源

1. **提示词编译只有一个实现。** 前台 UI、后台服务、离线兜底、Web 端**全部消费同一份编译产物**，禁止任何一处私自拼装 system prompt。
2. **编译产物是版本化契约**，必须携带 `schemaVersion` + `compilerVersion`，并以 golden 测试锁死语义；文案或段序的任何变动都必须显式更新 golden 并说明原因。
3. **每个概念只有一个定义。** 工具函数、头像解析、HTML 转义、时间格式化、金额运算、身份键（`memberType:memberId`）——各只能有一处实现，放在 `core:*` 并通过 lint 禁止重复定义。
   > 前身事故：8 份 `escapeHtml`、7 份 `esc`、5 份 `resolveAvatar`、3 份 `loadJSZip()`、2 套导出表清单（且已漂移）、同一份全表 schema 被抄 3 遍。
4. **模块间只经接口与事件通信。** feature 之间**零直接依赖**；需要协作时在领域层定义接口 + 事件流。
5. **禁止全局可变状态。** 不存在"全局当前角色 ID/当前会话 ID 被 20 个模块随意读写"这种结构；所有状态收敛到 ViewModel / 仓储 + 流。
   > 前身事故：399 处 `window.X =` 是唯一的模块机制；`global_api_preset_id` 被 18 个文件消费、`active_me_id` 被 23 个文件消费；同名函数靠脚本加载顺序决定归属。
6. **一个文件一个职责**：单文件 ≤ 500 行，单函数 ≤ 80 行。超出即拆分（前身有 9,426 行的单文件与 4,978 行的"样式+模板+业务三合一"文件）。
7. **不准靠"打补丁式自愈"吞掉格式异常。** 模型输出格式变化要在**解析器**里统一处理；禁止在多处 `replace()` 补 HTML、补括号、补闭合标签。
   > 前身事故：靠"自愈补丁"吞模型输出变化（补 `}`、补 `</think>`、删伪造字段），最终 49 处裸调用各自为政。

## 三、第三条宪法：真机特权与后台存活

1. **原生能力全部异步。** 所有平台能力以 `Flow` / `suspend` 暴露；**禁止任何同步阻塞的跨层调用**。
   > 前身事故：约 110 个桥方法全是同步的，会冻结整个 WebView 的 JS 执行；作者自己写下了这个坑，却只给 2 个方法加了异步变体。
2. **关键路径在原生。** 「收消息 → 决策 → 回消息」由原生服务承担，UI 只是观察者；UI 进程死亡不影响后台行为。
3. **最小必要保活 + 用户可一键全关。** 保活手段必须逐项可见、可关闭，关闭后**彻底释放**（无残留闹钟、通知、悬浮窗、WakeLock）。
4. **权限最小化。** 每个权限必须有明确用途、申请时机、被拒后的降级路径；能用 SAF 就不用全盘存储权限。
   > 前身事故：申请了 `MANAGE_EXTERNAL_STORAGE`（且越界防护只是字符串前缀比对）、`usesCleartextTraffic=true`、通知监听**解析了所有应用的通知**。
5. **诚实边界原则。** 平台做不到的事**必须如实告知用户**，不许用"加固"话术掩盖。
   > 前身事故：部分国产 ROM 的 force-stop 会清除应用注册的全部闹钟——**任何应用内代码都无法挽回**。旧版在这条路上反复"加固"过一轮才承认。本项目从第一天就把这条写进产品文案。
6. **密钥不进仓库。** 签名口令、API Key、后端密钥一律走环境变量 / CI Secret / Android Keystore（客户端）或服务端持有。
   > 前身事故：签名口令以明文字面量写在构建脚本里、keystore 被版本控制跟踪；一枚第三方 API Key 硬编码在前端资产里（前端可任意解包 = 已泄露）。
7. **原生 HTTP 代理必须有域名白名单。** 禁止任何"传任意 URL 就帮你请求"的通道。
   > 前身事故：原生层暴露了任意 URL + 任意 header 的 HTTP 代理，完全绕过 WebView 同源策略（SSRF / 数据外带）。

## 四、第四条宪法：可验证

1. **核心逻辑必须可单测。** 提示词编译、指令解析、记忆召回、游标分页、金额运算、备份序列化——**必须是纯函数或纯逻辑**，能在普通 JVM 单测里跑，不需要模拟器。
2. **红线必须有测试。** 至少这四个测试必须存在且常绿：
   - 提示词编译 golden（对旧版 oracle 逐字节对齐）；
   - 二进制入库守卫负向测试（挂在真实写入路径）；
   - **全表备份覆盖测试**（枚举所有表，断言都已在备份注册表里并完成往返）；
   - 十万条消息的分页性能测试（第 1 页与第 1000 页均 < 50ms）。
3. **CI 门槛**：编译 + 单测 + lint（含依赖方向与重复定义规则）+ 迁移测试。**红灯不合并。**
   > 前身事故：CI 只跑 `assembleDebug`，全仓 0 个测试文件。
4. **每个阶段有可验收的产出**，验收标准必须能被命令或真机清单自动/半自动复核。

## 五、第五条宪法：可演进

1. **不做一次性大爆炸重写。** 按里程碑分批交付，每个里程碑结束时产品可用。
2. **依赖锁定明确版本**，禁止 `latest.release` 之类的浮动版本。
3. **schema 变更必须编号管理**：每版一个 Migration + 一个测试，禁止"累积式 schema 声明"。
4. **平台边界前置评估**：动手前先问"这个能力在目标平台真的存在吗"，而不是做完了才发现不可用。
5. **允许放弃。** 当一条路被证明成本高于收益时，明确记录并放弃，而不是无限期维护半成品。

## 六、永久禁止清单（出现即返工）

**数据类**
- ❌ 把 base64 / data URL / 大 `ByteArray` 写入任何持久化层
- ❌ 无索引的全表查询后在内存里过滤
- ❌ 用 `OFFSET` 深翻列表
- ❌ 把大文本字段加入索引
- ❌ 静默吞掉存储/配额/序列化异常
- ❌ 备份表清单手工维护
- ❌ 把整库序列化成一个大字符串再写文件

**架构类**
- ❌ 全局可变单例/全局命名空间互调（`window.xxx` 式靠字符串找函数）
- ❌ feature 之间直接 import 实现类
- ❌ 单文件 > 500 行继续堆叠
- ❌ 同一功能在两处实现（含 Web 与 Android 各写一份内核逻辑）
- ❌ 用 JSON 字符串在层与层之间传数据（必须强类型）

**内核类**
- ❌ 在多处拼装 system prompt
- ❌ 任意修改已约定的指令字面格式。**本项目保留前身的方括号字面格式**（`[VOICE]`/`[SENDER:]`/`[PLAY_MUSIC]`/`[RED_ENVELOPE]` 等），理由是降低人机摩擦——这些格式已被大量角色卡、世界书与提示词资料沿用，改语法等于让所有存量资料失效。**格式一旦随 V1 发布即冻结**；如需演进，必须走"新增别名、旧格式长期兼容"的路线，不许直接改义。
- ❌ 指令解析失败导致崩溃（必须降级为纯文本）

**平台类**
- ❌ 同步阻塞的跨层/跨进程调用
- ❌ 把密钥/口令写进源码或仓库
- ❌ 任意 URL 的原生网络代理
- ❌ 用"应用内代码"去对抗系统级 force-stop（做不到，别浪费工期）

## 七、给实施者的工作方式（本项目特有）

1. 实施在新窗口中逐阶段推进，**每个阶段开始前先读本文件**。
2. 每完成一个模块，输出：变更文件清单 + 关键设计决策 + 测试命令与**真实输出**。
3. 遇到架构歧义时：先给 2~3 个方案对比（含取舍），**不要擅自选择**，等决策。
4. 代码注释与文档用中文，变量名/API 用英文。
5. **不确定就说不确定**，不许编造测试结果、不许声称已验证未验证的东西。
6. 每阶段结束跑一遍 §四.3 的 CI 门槛与对应验收清单，**未过不许进入下一阶段**。
