## 一、产品形态

### 1.1 核心体验循环（一切设计围绕它）
```
用户打开 → 落在拟真桌面（看到时间、壁纸、角色桌宠、未读红点）
        → 点开某个角色的对话
        → 打字/发语音/发图/发红包
        → 角色流式回复（有思考、有情绪、有动作、可能发来语音/图片/位置/转账）
        → 角色记得很久以前的事，也会主动找你
        → 关掉 App 后，角色仍然按自己的时间线生活并给你发消息
```
**判定一个功能是否值得做，只问一句**：它是否让"角色真实地生活在这台手机里"这件事更强？答不上来的，砍掉。

### 1.2 三条不可妥协的产品体验
| # | 体验 | 判据 |
| :--- | :--- | :--- |
| E1 | **长周期记忆**：三个月前说过的话，今天能被自然提起 | 召回测试：注入 300 轮历史后，问"我上次说的那个事"，角色能答对 |
| E2 | **后台活着**：关掉 App 后仍能收到角色的主动消息并自动回应 | 真机锁屏 30 分钟，至少收到并自动回一条 |
| E3 | **永远不卡不崩**：十万条消息、整本小说导入、上千张图片 | 见宪法 §一、§四.2 的四个红线测试 |

### 1.3 功能分层（防范围蔓延）
前身做了 19 个应用、约 106k 行前端代码，结果是核心对话的体验被摊薄。本项目**明确分层**：

**Tier A · 核心（V1 必须交付，占总工程量 ~45%）**
- 拟真桌面外壳（状态栏、图标网格、Dock、壁纸、小组件、翻页）
- **单聊**：流式打字机、引用/撤回/多选/重新生成、语音条、图片、位置、红包、转账、通话记录、系统灰字、消息搜索、聊天美化
- 角色档案（人设、外貌、母语、关系网）与用户面具（多身份切换）
- 世界书（关键词触发的设定注入）+ 提示词拓扑与调试 Trace 面板
- 三层记忆（核心记忆 / 摘要 / 向量召回）+ 记忆管理界面
- 多协议 LLM 配置（OpenAI 兼容 / Anthropic / Gemini / 自定义）、流式、超时重试、取消
- 通知（渠道 + 富通知 + **通知栏快捷回复**）、精确闹钟（角色能给你设真闹钟）
- 后台保活与原生自动回复

**Tier B · 世界感（V1.5，~30%）**
- 群聊（多角色一次响应内自行分配发言、群公告、群投票、群管家）
- 朋友圈（发布、AI 角色自动发布与互动、可见人分组）
- 线下剧场 / 赴约（白描小说叙事、字数区间、双 POV）
- 情侣空间（日历、相册、手账、悄悄话一期制、纪念日倒数）
- 音乐（本地曲库 + 在线直链、歌词、**原生后台播放**、角色点歌）
- 桌宠（9 状态悬浮窗、双击互动、主动搭话）
- 仪轨（四维当日状态：日程/穿着/随身物/位置 + 生理期/生病）
- 书城（TXT 导入零感知、AI 续写、段落级伴读短评）

**Tier C · 玩法（V2 及以后，按需，~25%）**
- 论坛（AI 社交网络、马甲、下拉批量生成）
- 查手机 / 反查手机（进入角色手机、风险等级、角色察觉）
- 快穿局（世界观/身份/剧本 + 变量 + 弹幕）
- 心动游戏（乙游：好感阶梯、抽卡保底、立绘热区、剧情分支）
- 购物 / 钱包扩展玩法、提现小游戏
- 工作台 Agent（手机端编码 Agent、抓网页、工具调用）
- 小程序沙箱（**必须真隔离**，见 §五）
- 小助手（应用内帮助，知识库外置为可版本化文档）

> **裁剪原则**：Tier C 的每一项都可以在实施时基于"用户是否真的在用"决定是否续做。**但 Tier A 的三条体验不可妥协。**

### 1.4 前身功能的取舍表（照搬 / 改造 / 丢弃）
| 前身功能 | 本项目决策 | 理由 |
| :--- | :--- | :--- |
| 深度优先级提示词拓扑 | **照搬并重构为唯一实现** | 被验证有效，是本项目灵魂 |
| 三层记忆 + 时间衰减只排序 | **照搬算法语义** | 作者明确修过"久远记忆永不召回"的 bug |
| `[SENDER:名]` 群聊一次响应多角色 | **照搬** | 语义优雅，且避免前端调度器 |
| 入库级"主权防火墙"（防模型冒充用户） | **照搬** | 数据完整性关键 |
| 指令协议（25 类方括号标记） | **格式照搬、实现改造**：字面格式保留（宪法 §六），内部收敛为统一注册表 + 流式增量状态机 | 前身散落在多处正则、格式一变就崩；但方括号格式已被大量角色卡/世界书资料沿用，改语法等于让存量资料失效 |
| 上下文窗口 | **推翻重做**：装真实 token 预算 + 分层裁剪 | 前身硬编码"只发最近 10 条" |
| 多协议支持 | **推翻重做**：前身的 `protocol` 字段是死的，Gemini 必失败 | 前身只有 UI 幻觉 |
| 备份/恢复 | **推翻重做**：schema 注册表驱动 + 全表覆盖测试 | 前身漏 44/87 张表，换机即丢数据 |
| 金额 | **推翻重做**：整数分 + 事务 + 唯一约束 | 前身浮点元 + 无幂等 |
| 保活手段（1×1 悬浮窗 + 静音音频循环） | **丢弃** | 那是为对抗 WebView 冻结而堆的；原生 App 不需要 |
| 小程序"同 realm 执行" | **丢弃**，改真隔离沙箱 | 前身小程序能摸到宿主 DB 与原生桥 |
| 加密（XU1 + 硬编码口令）、完整性校验（fail-open） | **丢弃** | 不是加密，且校验不生效 |
| `app_router.js` 式的"路由" | **丢弃**，用真正的导航图 | 前身那份没有提供任何路由能力 |
| 双态运行模式（成员/旁白） | **保留**（群聊旁白灰字是有效体验） | 用户已习惯 |
| 群管家惰性补推 | **保留** | 低功耗，用户已依赖"打开才补" |

## 二、平台与技术形态

### 2.1 为什么是「KMP 共享内核 + 双原生 UI」
```
        ┌────────────────────────── 共享内核（唯一实现）──────────────────────────┐
        │  shared/  (Kotlin Multiplatform: commonMain → androidMain / jsMain)     │
        │  · 提示词编译器 + 模板 + depth 表 + 编译产物契约                        │
        │  · 指令协议注册表 + 流式增量解析状态机                                  │
        │  · 记忆三层算法（摘要/召回/去重/余弦/时间衰减）                          │
        │  · 上下文预算与裁剪 · 世界书匹配引擎                                    │
        │  · 领域实体与校验 · 游标分页 · 金额运算 · 备份格式（manifest/注册表）     │
        │  · LLM 客户端抽象 + SSE 解析                                            │
        └───────┬────────────────────────────────────────────┬─────────────────┘
                │ androidMain 提供 actual 实现                │ jsMain 提供 actual 实现
                ▼                                             ▼
    ┌───────────────────────────┐                 ┌───────────────────────────┐
    │ Android App（Kotlin）      │                 │ Web / PWA（TypeScript）    │
    │ Compose UI + 导航图         │                 │ React UI + 路由            │
    │ Room + SQLite + 沙盒文件     │                 │ IndexedDB + OPFS          │
    │ 前台服务 / 闹钟链 / 通知      │                 │ Service Worker / Web Push │
    │ 蓝牙 / Media3 / ONNX / 悬浮窗 │                 │ WebAudio / WASM(可选)      │
    └───────────────────────────┘                 └───────────────────────────┘
```
- **内核只写一遍**（宪法 §二.1）：提示词编译、指令解析、记忆召回在两端**物理上是同一份代码**，由 Kotlin 编译到 JVM/Android 与 JS。
- **UI 各写一遍**：Android 用 Compose（拟真外壳 + 高性能列表），Web 用 React。**这是有意接受的重复**，因为两端交互范式与能力差异太大，强行共享 UI（Compose Multiplatform Web）会带来体积与性能风险。
- **设计 Token 也是单一来源**：由一份 token 定义生成 Compose Theme 与 Web CSS 变量（见 `09-DESIGN-SYSTEM.md`），保证两端视觉同源。

### 2.2 技术栈清单（全部锁定版本，禁止浮动版本）
| 层 | 选型 | 理由 |
| :--- | :--- | :--- |
| 共享内核 | **Kotlin 2.x Multiplatform**（单模块 `shared`，源集 `commonMain`/`androidMain`/`jsMain`） | 一套逻辑两端用；用单模块+源集而非多模块，降低构建复杂度（"怎么省事怎么来"） |
| 序列化 | kotlinx.serialization | 与 KMP 同源；编译期生成，无反射 |
| 并发 | kotlinx.coroutines + Flow | 结构化并发；**禁主线程 IO** |
| Android UI | Jetpack Compose（Material 3 Expressive）+ Navigation Compose | 原生渲染，无 DOM 爆炸；共享元素转场与毛玻璃能力足够 |
| Android 数据 | **Room + SQLite** + Paging 3（游标分页） | 索引/事务/迁移/分页齐备；替代旧版 IndexedDB |
| Android DI | Hilt | 编译期校验，防全局单例 |
| Android 异步任务 | Coroutines + WorkManager（周期任务保底）+ 前台服务（关键路径） | 关键路径不依赖 UI 进程 |
| Android 网络 | Ktor Client（OkHttp 引擎）+ 自写 SSE 解析 | 超时/重试/取消可完全掌控 |
| Android 媒体 | **Media3 / ExoPlayer** + MediaSession | 旧版用裸 `MediaPlayer`，缺音频焦点与后台策略 |
| Android 图片 | Coil 3（直接以 `File` 为数据源） | 禁止"读进内存再转 Bitmap" |
| Android 本地推理 | ONNX Runtime Android（**锁定明确版本号**）+ 量化 all-MiniLM-L6-v2（384 维） | 离线语义召回 |
| Android 保活 | 前台服务（`specialUse`）+ 链式精确闹钟 + 开机自启 + 电池白名单引导 | 见 `06-NATIVE-ANDROID.md` |
| Web 构建 | Vite + TypeScript 5（strict） | 快、够用 |
| Web UI | React 19 + Tailwind CSS（消费同一份 token） | 生态成熟；虚拟列表用 TanStack Virtual |
| Web 状态 | Zustand（切片） | 轻，不做全局大对象 |
| Web 存储 | IndexedDB（结构化）+ **OPFS**（二进制） | 与宪法 §一 的"二进制外置"等价 |
| Web 离线 | Service Worker（**资源清单由构建产物生成**） | 旧版手写清单漂移了 29 项 |
| 测试 | JUnit5 + Turbine + Room in-memory + Robolectric（Android）；Vitest（Web）；**golden 测试（跨语言共用）** | 核心逻辑必须能在 JVM 单测里跑 |
| 构建 | Gradle KTS + Version Catalog（`libs.versions.toml`）；Web 用 pnpm | 一处锁版本 |
| CI | GitHub Actions：编译 + 单测 + lint（含依赖方向/重复定义规则）+ 迁移测试 + 出包 | 红灯不合并 |

**明确不选**：Flutter（额外工具链 + 拟真系统 UI 对抗框架）、原生 iOS（用 Web 覆盖）、Tauri/Electron 桌面端（不在本期范围）、任何把核心逻辑放在 WebView 里的方案（违反宪法 §〇）。

### 2.3 Web 端的定位（重要）
> Web 端的使命是**覆盖 iOS 用户**，不是"顺便做个网页版"。

因此：
- Web 端**必须是一个可安装的 PWA**，且核心对话体验与数据同步要完整可用；
- 但**后台行为在 iOS 上注定受限**（页签被冻结、无可靠周期任务、Web Push 需已安装到主屏）。本项目**如实承认**这一点，并把"角色主动发消息"改为**双轨**：Android 侧本地调度；Web/iOS 侧由服务端定时任务 + Web Push/邮件兜底。详见 `08-WEB-AND-IOS.md`。
- Web 端**不做**悬浮窗桌宠、系统闹钟直写、蓝牙、本地 ONNX 全量推理（可降级 WASM）。

### 2.4 是否需要后端
需要，但**只做最小集**：
1. 鉴权（账号、设备管理、会话撤销）；
2. 云备份（端到端加密，服务端只见密文）；
3. 可选的定时任务 + 推送（供 Web/iOS 补齐后台能力）；
4. **不代理 LLM 请求**（除非用户自建网关）——API Key 由用户自己填，在 Android 上存 Keystore，在 Web 上存服务端会话或本地加密后存储。**绝不允许把 Key 硬编码进前端**。
> 前身教训：前端资产里硬编码了一枚第三方 API Key（可被任意解包）；云备份表对 anon 开放 `FOR ALL USING(true)`，任何持 key 者可读写他人备份。

## 三、产品原则（写进 UI 文案与交互决策）

1. **拟真优先**：用户第一眼要以为这是一台真手机。任何"网页感"的控件（原生滚动条、系统弹窗样式不统一、双击缩放）都必须消除。
   > 前身教训：自称禁止原生弹窗，实际仍有 13 处 `alert/confirm`。
2. **离线优先**：先进入桌面，再后台校验登录态；不要让用户对着加载动画等。
3. **可见的诚实**：做不到的事要说（例："为保证后台收信，需要把本应用加入电池优化白名单"；"部分国产系统清理后台后闹钟会失效，这是系统限制"）。
4. **数据属于用户**：一键导出完整备份（含所有媒体）、一键清空、一键迁移；导出格式有版本号与校验和。
5. **不做静默失败**：任何写入失败、配额不足、同步冲突都必须在界面上出现。

## 五、明确划出的安全红线（产品级）
1. **小程序必须真隔离**：独立运行环境 + 显式能力清单，未声明的能力**默认无权限**。
   > 前身教训：小程序用 `new Function` 在宿主同 realm 执行，能读宿主数据库与原生桥；未声明 permissions 的旧小程序**默认全权限**，且会拿到明文 API Key。
2. **HTML 互动卡**继续走 `iframe sandbox`（前身这是唯一做对的真沙箱）。但需补：**渲染时实施 CSP 限制**（`connect-src: none`）。
3. **账号与云备份**按 `auth.uid()` 做行级隔离；备份内容端到端加密。
4. **日志脱敏**：API Key 只显示后 4 位；用户消息正文不进日志。
