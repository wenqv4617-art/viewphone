# 05 · 双端权限与 Android 原生能力（合规 + 实现）

> 依据：`00-CONSTITUTION.md` §三（真机特权与后台存活）、§六（永久禁止清单）。
> **本文两部分**：§0–§4 与 §6–§8 是**跨端权限与合规**（含上架材料）；§5 起为 **Android 原生能力与特权实现**（能力矩阵、保活分层、进程结构、抽象层、安全基线、验收）。
> 冲突口径：以宪法为最高，其次以本文为准；`06/07/08` 三份是各自领域细节。

## 0. 一句话结论与权限哲学

**结论：微光机只申请「收得到消息、活得下去、你点了才用」这三类权限，其余一律不申请；每个权限都有诚实用途、明确时机、被拒降级与一键关闭。**

| # | 哲学 | 硬要求 |
| :--- | :--- | :--- |
| P1 | **最小必要** | 每个权限绑定一个具名能力（`PlatformCapabilities` 的接口），绑不上就不写进清单；能用 SAF / Photo Picker 就不要全盘权限。 |
| P2 | **如实告知** | 申请前说清"干什么用、不给会怎样"；平台做不到的事直接写进文案，**不许用"加固/优化体验"掩盖**。 |
| P3 | **可一键关闭** | 每个能力一个显式开关，**默认不静默开启**；关闭后彻底释放（§5.1），`dumpsys` 零残留可复核。 |
| P4 | **被拒有降级** | 权限被拒产品仍可用，只是能力变弱；**禁止**把授权当作进入 App 的前置条件。 |
| P5 | **状态可见** | 设置页常驻展示每个能力的当前状态与上次心跳时间。 |

> 政策风险：Play 对过度申请（全盘存储、无障碍、精确闹钟、通知使用权）有独立审查口径，下架成本远高于省下的开发时间。
> 旧版教训：旧版同时踩了 `MANAGE_EXTERNAL_STORAGE`（越界防护只是字符串前缀比对）、`usesCleartextTraffic=true`、通知监听解析**所有应用**的通知。

## 1. Android 权限总表

`危险级`：**运行时**=弹窗同意｜**特殊访问**=跳系统设置页单独开｜**普通**=安装即授予、权限页无法单独关（只能靠应用内开关）。
`可关闭`：**开关**=应用内开关+系统双保险｜**仅应用内**=系统页不可见｜**随包**=随包声明、由应用内开关决定是否使用。

| 权限 | 用途（用户能懂的话） | 能力 | 危险级 | 申请时机 | 被拒后的降级 | 设置页 | 可关闭 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `INTERNET` | 和 AI 模型、云备份通话 | Connectivity | 普通 | 随包 | 离线模板 + 标注"离线模式"，**不伪造 AI 输出** | — | 随包 |

| `FOREGROUND_SERVICE` | 让"收→回"在后台持续跑 | Background | 普通 | 随包 | 无替代；服务本身由总开关关停 | — | 随包 |
| `FOREGROUND_SERVICE_DATA_SYNC` | 长连接同步（收消息） | Connectivity | 普通 | 随包 | — | — | 随包 |

| `CAMERA` | 拍一张发给角色 | Capture | 运行时 | 用户点"拍摄"时 | 只能从相册（Photo Picker）选图 | App 详情页 | 开关 |

| `BIND_NOTIFICATION_LISTENER_SERVICE`（通知使用权） | **仅**读"正在播放"与媒体控制 | Media | 特殊访问 | 用户点"连接正在播放"时 | 该卡片不显示，**其余完全不受影响** | `ACTION_NOTIFICATION_LISTENER_SETTINGS` | 开关（关即解绑） |

### 1.1 明确**不申请**的权限与理由

| 权限 / 能力 | 理由 |
| :--- | :--- |
| `MANAGE_EXTERNAL_STORAGE` | 过度授权；Play 仅允许文件管理/备份类核心功能使用，消息应用声明必被拒。改用 SAF。<br>> 旧版教训：用它读写公共目录，越界防护只是**字符串前缀比对**，等于没防。 |
| `USE_EXACT_ALARM` | 虽是普通权限，但 Play 只允许**闹钟/日历类**应用的核心功能使用；消息类应用声明属违规风险。走 `SCHEDULE_EXACT_ALARM` + 引导。<br>> 政策风险：为省一次引导把上架资格押上去。 |
| `AccessibilityService`（无障碍） | 开启后进程存活率确实提升，但本项目**没有"代操作其他 App"的正当需求**，Play 审核极严且可下架。**不接受以无障碍换保活。** |
| `READ/WRITE_EXTERNAL_STORAGE`（旧） | 13+ 已废弃、10+ 受分区存储限制；保留只会触发"冗余权限"提示，并诱导走回全盘路径。 |
| `ACCESS_BACKGROUND_LOCATION` / `QUERY_ALL_PACKAGES` / `PACKAGE_USAGE_STATS` / `REQUEST_INSTALL_PACKAGES` | 无正当需求，且均属需专项说明的高敏能力；后台定位与使用情况访问收益为零。 |
| `SCHEDULE_EXACT_ALARM` 之外的 Doze 绕过手段 | 保持"最小必要保活"（06 §2）；不用不可见窗口或静音音轨欺骗系统。 |

> 旧版教训：旧版保活默认全开（1×1 透明悬浮窗 + 静音 `AudioTrack`），用户无从关闭。本版**每项都是显式开关**，悬浮窗只服务桌宠。

## 2. iOS / Web 侧能力与授权

类：**A**=Android 独有｜**B**=双端都有｜**C**=Web 受限｜**D**=Web 不可用。未真机实测者标 **[需真机验证]**。

| 项 | 类 | Web/iOS 的"权限"形态 | 时机与文案 | 无对应能力时 |
| :--- | :--- | :--- | :--- | :--- |
| 通知（Web Push） | C | `Notification.requestPermission()`；**iOS 16.4+ 仅"已添加到主屏幕"的 PWA 可用** [需真机验证] | 完成一次有意义动作后申请，**不在首屏**；「装到桌面才能收到角色的消息」 | 邮件/短信兜底 + 打开时"未读汇总"；**未安装主屏必须收不到**（负向断言） |
| 存储持久化 | C | `navigator.storage.persist()` 的返回值决定数据是否可能被清；Safari 可能"7 天未使用即清理" [需真机验证] | 首屏即申请（**拿不到不阻塞**） | 明示"浏览器可能清除本站数据，请定期导出"；**E2E 云备份为权威副本** |
| 配额 | C | `navigator.storage.estimate()` | 批量导入前展示 `usage/quota` | 超 80% 提示清理；**禁止静默失败** |
| 后台定时 / 自动回复 / 锁屏投递 | D | **无任何授权项**，是 WebKit 架构边界 | 文案写明"关掉页面后角色不能自己动" | **服务端定时 + Web Push** 发起；端侧改为"下次打开补发/补回" |
| 通知栏快捷回复 | D | **无 RemoteInput 对应物** | — | 通知文案一句话可读完；点击直达输入框并预聚焦 |
| 系统闹钟直写 | D | iOS 无系统闹钟 API | 明说差异 | 日历 `.ics` 导入或应用内提醒 |
| 悬浮窗桌宠 | A | 无系统级悬浮窗 | — | 页内 DOM 桌宠；**跨 App 陪伴只承诺 Android** |
| 蓝牙 BLE | D | **iOS Safari 不支持 Web Bluetooth** | — | 隐藏 BLE 入口，提示"请在 Android 端配对" |
| 振动 | C | **iOS 不支持 Vibration API** | 调用前特性检测 | 视觉 + 短音效替代，**不当主反馈** |
| 麦克风 / 相机 | B | `getUserMedia` / `<input capture>`（HTTPS + 用户手势为前置） | 用户点"拍摄/录音"时 | 只能文字 + 相册 |
| 剪贴板读取 | C | iOS 对脚本读剪贴板有系统级粘贴提示与限制 [需真机验证] | 只在用户显式点"粘贴"时读 | 用户手动长按系统粘贴 |
| 屏幕常亮 / 后台音频 | C | Screen Wake Lock API；后台音频无独立授权项，切后台可能被暂停 [需真机验证] | 朗读/播放时申请 | 不常亮改为提示；长音频服务端生成后点击播放 |
| 本地 ONNX 推理 | C | 无权限项，受内存与回收限制 | — | 小模型 WASM + 预热；重模型走服务端 |
| **iOS/Web 完全没有的授权入口** | — | 前台服务、精确闹钟、电池优化白名单、开机自启、通知使用权、悬浮窗、无障碍 | 这七项**不得出现在 Web 端 UI 里**（不做"点了没反应"的按钮） | 见上各行 |

> 旧版教训：旧版让同一套资产同时服务 WebView 与 PWA，又让 PWA 假装拥有原生能力——**边界的含糊直接变成信任损失**。

## 3. 权限 ↔ Tier 功能映射矩阵（产品与客服说明书）

最后一列是客服话术依据，**必须与 App 内实际行为逐字一致**。

| 功能（Tier） | Android 需要什么 | iOS(Web) 需要什么 | 缺权限时降级成什么样 |
| :--- | :--- | :--- | :--- |
| 聊天核心：打字/流式/历史/搜索（A） | `INTERNET` | 无额外授权 | 断网 → 离线只读 + 排队发送 |
| 图片/语音/位置消息（A） | `CAMERA`/`RECORD_AUDIO`/`ACCESS_COARSE_LOCATION`（相册走 Photo Picker 零权限） | `getUserMedia` 按需 | 拒拍照/录音 → 只能相册选图或打字；拒定位 → 手输城市 |
| 红包/转账/账务（A） | 无额外权限（服务端 + 本地幂等键） | 无 | — |
| 角色主动找你 · 通知（A） | `POST_NOTIFICATIONS` + 通知渠道 | 通知授权 + **已安装主屏** | 应用内未读汇总 + 兜底闹钟；iOS 未安装主屏 → 收不到 |
| 后台活着：收→决策→回（A） | `FOREGROUND_SERVICE(+_SPECIAL_USE)` + `WAKE_LOCK` + `RECEIVE_BOOT_COMPLETED` | **不可用**（D 类） | 服务被关 → 只在打开时收；force-stop 后依赖下次启动补录（**如实记录，不判失败**） |
| 准时提醒 / 系统闹钟（A） | `SCHEDULE_EXACT_ALARM`（→ `ACTION_SET_ALARM`） | 不可用 | ±15min 误差的应用内提醒；无时钟应用 → 仅应用内 |
| 一键全关后台 / API 配置 + Trace（A） | 无需权限（Key 存 Keystore） | 无（Key 存服务端会话或本地加密） | — |
| 音乐：本地+在线+后台播放（B） | `FOREGROUND_SERVICE_MEDIA_PLAYBACK`；曲库走 **SAF**（不用 `READ_MEDIA_AUDIO`） | 只能前台播放 | 切后台可能暂停；iOS 明确告知"打开时播放" |
| 「正在播放」读取（B） | **通知使用权**（只解析媒体类通知） | 不可用 | 该卡片不显示，其余不受影响 |
| 桌宠（B） | `SYSTEM_ALERT_WINDOW` | 无悬浮能力 | 页内桌宠；iOS 只承诺页内桌宠 |
| 蓝牙配件（B） | `BLUETOOTH_SCAN`/`CONNECT`（≤11 另需细定位） | **不可用** | 入口置灰并说明原因 |
| 语音朗读 TTS（B） | 无权限（依赖系统引擎，走 `<queries>`） | Web Speech API [需真机验证] | 无中文引擎 → 纯通知 + 文字 |
| 备份导出/导入（B） | **SAF**（`ACTION_CREATE_DOCUMENT`/`OPEN_DOCUMENT`） | 浏览器下载 + OPFS + `persist()` | 无持久化授权 → 提示"定期手动导出" |
| 群聊/朋友圈/剧场/情侣空间/仪轨/书城（B） | 无额外权限 | 无 | 仅受网络与存储配额影响 |
| 论坛/查手机/快穿局/心动游戏/购物（C） | 无额外权限（纯应用内数据） | 无 | — |
| 工作台 Agent（C） | `INTERNET` + **`ToolGateway` 白名单**（门禁而非权限） | 服务端网关 | 目标域名不在白名单 → 直接拒绝并说明 |
| 小程序沙箱（C） | **无系统权限**，能力由显式清单授予 | 同 | 未声明能力 → 该 API 不可用；隔离失败 → 不运行 |

> 政策风险：Tier C 的工作台与小程序最容易演变成"任意 URL 代理"和"宿主同 realm 执行"——**这两条是宪法 §六 的永久禁止项**。

## 4. 首次启动引导流程（4 步，每步可跳过）

原则：**不请求任何权限就能开始用**；**不在启动时批量弹窗**；跳过时给出具体后果。

| 步 | 时机 | 申请/引导 | 用户可见文案 | 可跳过 | 跳过后的提示 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 0 | 冷启动 | **什么都不申请** | 「先挑一个角色，聊两句。」 | — | — |
| 1 | 用户**发出第一条消息之后** | `POST_NOTIFICATIONS` | 「现在可以开通知了：你退出 App 后角色发消息时，你才会看到。不开的话，只有你打开 App 才能看到未读。」 | 可 | 「已跳过。未读会在你下次打开时显示。」设置页常驻"打开通知"入口 |
| 2 | 用户在设置里主动开「后台能力」 | 电池优化白名单 + `SCHEDULE_EXACT_ALARM` + 厂商自启指引（按 `Build.MANUFACTURER` 分发小米/华为/OPPO/vivo/魅族/三星/原生文案） | 「这三项决定角色能否在你锁屏时准时找你：①关电池优化，避免省电时掐断接收；②允许精确闹钟，让约定时间准点到达；③允许自启动，重启后自动恢复。」 | 可，**每项独立开关** | 「你跳过了③：重启手机后要打开一次 App，接收才会恢复。」 |
| 3 | 用到才问（**分散在功能入口**） | 通知使用权、`SYSTEM_ALERT_WINDOW`、蓝牙、定位、相机/麦克风 | 「开启后角色能知道你正在听什么并跟着点歌。**只读正在播放的音乐，不读其他通知。**」 | 可 | 「这项没开只影响『正在播放』这一张卡片，其他都能用。」 |

### 4.1 反面文案（禁止出现在任何界面）

| ❌ 禁止写法 | 为什么不行 | ✅ 改成 |
| :--- | :--- | :--- |
| 「为了更好的体验，请允许所有权限」 | 空话，且"所有权限"违反最小必要 | 逐项说"干什么用 + 不开会怎样" |
| 「本应用需要后台权限以保证正常运行」 | 恐吓式，"正常运行"不可验证 | 「不开的话，你锁屏期间收不到角色消息，要等你打开 App」 |
| 「请授予存储权限以保护你的数据」 | 与事实不符：导出走 SAF，不需要全盘权限 | 「备份会保存到你选择的那一个文件夹，我们只写那一个」 |
| 「开启无障碍可提升后台稳定性」 | 用高敏权限换保活，**本项目不做** | 不提供该入口 |
| 「我们承诺绝不收集任何数据」 | 调用第三方 LLM 必然发送对话内容，属虚假陈述 | 「发给模型的内容由你填的 API Key 决定；我们不代理你的模型请求，也不留存消息正文」 |

> 旧版教训：旧版厂商自启引导文案是好资产（可直接沿用），但**保活默认全开、用户无从关闭**——好文案救不了坏默认。

### 5.1 一键全关与「彻底释放」核对清单

**「关闭全部后台能力」是原子动作**：任一步失败要记录并可重试，UI 显示"已完成 7/9"这类可核对进度而不是转圈。实现 9 项见 `06` §2.3；本节定义**用户能看到什么**：

1. ✅ 核心服务已停止；2. ✅ 全部定时闹钟已取消；3. ✅ 全部后台任务已取消；4. ✅ 网络长连接已断开；5. ✅ 全部通知已清除；6. ✅ 桌面桌宠已移除；7. ✅ CPU 唤醒锁已全部释放；8. ✅ 屏幕/电量监听已解除；9. ✅ 待发消息已标记"已取消"（下次启动不会偷偷发出）。

**可复核命令**（真机清单，06 §7.3）：`dumpsys alarm | grep <pkg>` 无输出 · `dumpsys power | grep -i -A2 <pkg>` 无 `PARTIAL_WAKE_LOCK` · `dumpsys notification --noredact | grep <pkg>` 无活动通知 · `dumpsys window windows | grep <pkg>` 无 overlay · `ps -A | grep <pkg>` 无 `:core` 进程。

> 旧版教训：旧版关闭"保活"只停了一个定时器，闹钟、悬浮窗、WakeLock 全残留——**"看起来关了"比"没关"更糟**。

## 6. 上架与合规材料清单

### 6.1 Google Play 数据安全表单（Data safety）

| 表单问题 | 我们的答案 |
| :--- | :--- |
| 是否收集/共享数据 | **是**，仅"应用功能"用途；消息正文经**用户自填的 Key** 发往其选定的模型服务商 |
| 数据类型 | ① 消息与对话内容；② API Key（仅本机 Keystore 加密）；③ 邮箱/账号（仅云备份）；④ 崩溃日志（**仅用户同意后**且已脱敏）。无通讯录、无位置后台上报、无广告标识符 |
| 传输是否加密 | 是（全站 HTTPS，`usesCleartextTraffic=false`） |
| 能否请求删除 | 能：应用内一键删除 + 云端删除（含分片与对象存储） |
| 是否与第三方共享 | 仅当用户主动配置模型服务商时；**不代理 LLM 请求**，服务端只见密文备份 |
| 敏感权限声明 | ① `SCHEDULE_EXACT_ALARM` 用途说明；② 前台服务 `specialUse` 用途说明 + 演示视频；③ **通知使用权仅用于媒体控制**，附"代码层过滤非媒体通知"说明 |
| 目标 API 级别 | **待定**（§9 D1）：`targetSdk ≤ 32` 与 ≥ 33 对应不同的 `SCHEDULE_EXACT_ALARM` 合规路径；**绝不申请 `USE_EXACT_ALARM`** |

### 6.2 隐私政策必须写明的条目

1. **收集什么**：对话内容、用户自填 API Key（本机加密）、账号邮箱（仅云备份）、可选的脱敏崩溃日志。
2. **不收集什么**：通讯录、通话记录、短信、其他应用列表、剪贴板内容、其他应用的通知（**只读媒体类通知**）、精确位置（只取粗定位且可手输替代）。
3. **发给谁、为什么**：用户自配的模型服务商（对话内容）；自建后端（仅鉴权、密文备份、可选推送）。
4. **加密与密钥归属**：云备份端到端加密，**服务端只见密文、不持密钥**；明示"**丢失口令等于丢失数据**"。
5. **保留多久、怎么删**：保留期限 + 一键删除的实际行为（含分片与对象存储）。
6. **权限清单与降级后果**：逐项列出，与 App 内设置页文案**逐字一致**。
7. **儿童与跨境**：不作为儿童向产品；涉及境外服务商时说明数据出境情形。
8. **变更通知方式**：政策变更如何在使用中提示。

### 6.3 iOS（Web 应用）侧的隐私说明

不做原生 iOS，**不涉及 App Store 隐私标签**；但 PWA 必须提供可达的隐私政策页且"安装前可读"，并明示：**未添加到主屏幕时 iOS 不会向网页推送通知**（这是功能开关，不是增长手段）；Safari 可能在长期未使用后清理本站存储，**云备份才是权威副本** [需真机验证 7 天清理策略]。不得写"绝不收集数据"这类与事实不符的表述。

### 6.4 「我们收集 / 不收集什么」一页声明（可直接贴进设置页）

| 我们收集 | 用途 / 存在哪 |
| :--- | :--- |

| 你填的 API Key | 用你自己的额度调模型；Android 存 Keystore，Web 存服务端会话或本地加密 |
| 账号邮箱 | 云备份与多设备；自建后端 |

| 我们不收集 | 说明 |

逐条对应宪法 §三与前身实证（完整证据链见 `D:\deepseek\Xvshishi_Rebuild_Proposal.md` §3 与 `D:\deepseek\对话与AI内核考古报告.md`）：
