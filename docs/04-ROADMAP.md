# 微光机 ViewPhone · 实施路线图与验收门槛

> 依据：`00-CONSTITUTION.md` 第四、五条。本文档是**执行入口**：阶段划分、交付物、验收门槛、启动指令。
> 估时口径：**单人 + AI 助手**，全职投入。可并行处已标注。**门槛未过不许进入下一阶段**（宪法 §七.6）。

## 一、里程碑总览

```
M1 ── 地基可信 ──────────► M2 ── 能聊天 ──────────► M3 ── 用得住 ──────────► M4 ── 上架级
   P0 + P1 + P2                P3 + P4                    P5 + P6                    P7
   "红线全部可验证"            "单聊跑通 + 后台活着"        "长期记忆 + 世界感"          "双端 + 云 + 发布"
```

> **本项目不设日历排期。** 节奏由产出速度决定，不由文档规定。这里只有**依赖顺序**与**验收门槛**：上一步没通过验收，下一步不许开始。

| 里程碑 | 结束时你能做什么 | 不可妥协的验收 |
| :--- | :--- | :--- |
| **M1 地基可信** | 内核与数据层全部可单测；红线测试常绿 | 提示词 golden 通过；10 万条消息第 1000 页 < 50ms；备份全表覆盖通过；base64 写入被生产路径拦截 |
| **M2 能聊天** | 真机上拟真桌面 + 单聊，流式回复，角色能设真闹钟，锁屏后仍能收到并自动回 | 锁屏 30 分钟端到端通过；长对话 5,000 条不掉帧；Trace 面板能解释"模型为什么这么说话" |

| **M4 上架级** | Android 出包 + Web PWA 上线 + 云同步/账号 | iOS 真机验收清单逐条过；双端同一份备份可互导；CI 全绿并自动出包 |

## 二、阶段明细（P0–P7）

### P0 · 仓库与工程基线
**交付物**
1. `D:\deepseek\viewphone` 仓库骨架（见 `02-ARCHITECTURE.md` §一）；`git init` + **首次提交**（宪法实施前提：没有基线就没有回滚）。
2. `gradle/libs.versions.toml`：所有依赖锁定明确版本，**禁 `latest.release`**。
3. `shared` KMP 模块可空跑：`./gradlew :shared:jvmTest` 通过。
4. `core:*` / `feature:*` 空模块 + Detekt 规则（跨 feature import、`shared` 平台 API、文件行数、函数行数、`System.currentTimeMillis()` 直调）。
5. CI：`.github/workflows/ci.yml`（编译 + 单测 + lint + 后续迁移测试）。
6. `design/tokens.json` → 生成 Compose Theme 与 Web CSS 变量（见 `09-DESIGN-SYSTEM.md` §9）。
7. 密钥纪律：签名配置读环境变量；`.gitignore` 覆盖 `*.jks`/`*.keystore`/`local.properties`；**从第一天就不许出现明文口令**。

**验收**
- `./gradlew build` 通过；CI 绿灯；故意写一个"跨 feature import"能让 CI 红灯（验证规则真的生效，而不是写了没接）。

### P1 · 共享内核 ★ 最高价值
**交付物**（全部在 `shared/commonMain`，纯 Kotlin，可 JVM 单测）
1. `ai/compiler`：`PromptSegment` / `Depth` 常量表（唯一来源）/ `PromptCompiler` / `CompiledPrompt`（含 `systemPrompt`、`messages`、`segmentsTrace`、`groupCharCounts`、`schemaVersion`、`compilerVersion`）/ 线上与线下两套装配器（**线下必须含 `-50/-40/-30` 段**）。
2. `ai/directives`：`DirectiveRegistry` + 全部指令解析器（保留前身已固化的字面格式）+ **流式增量状态机**（含"指令被拆散在多个 chunk""超长未闭合""格式异常降级为纯文本"三类兜底）。
3. `ai/memory`：摘要生成触发语义（`(pending - buffer) >= interval`）、结构化摘要解析（情感/事实/核心 + 关键词）、向量召回（余弦 + **时间衰减只参与排序** + 阈值判定用原始相似度 + TopK + 分组配额 + 排除已总结轮次 + 跳过最近 5 轮）。
4. `ai/context`：`ContextBundle` 定义 + **真实 token 预算与分层裁剪**（哪些永不裁、按什么顺序裁、裁剪决策进 trace）。
5. `ai/worldbook`：匹配引擎（关键词索引化，**禁止每请求全表扫描**）+ 5 个插入位 + `at_depth`。
6. `ai/client`：四协议适配（OpenAI 兼容 / Anthropic Messages / Gemini generateContent / 自定义）+ SSE 解析 + 超时/重试(指数退避)/错误分类/取消。
7. `domain/model`：核心实体（角色/面具/会话/消息/记忆/世界书/API 配置/钱包）+ 校验规则。
8. `data/pagination`：游标编解码（`(timestamp, id)`）+ 页大小上限。
9. `economy`：金额（`Long` 分）+ 账务规则 + 红包/转账幂等键设计。
10. **golden 测试**：用前身 `app_prompts.js` 的输出做 oracle，逐字节对齐（前身已有该测试范式与夹具，可直接移植其思想，但**必须以实测旧版为准重新对表**，前身新工程的 depth 表与实测不一致）。

**验收**
- `./gradlew :shared:jvmTest` 全绿；覆盖率：`compiler`/`directives`/`memory` 三个包 ≥ 85%。
- golden：给定 20 组输入 bundle，编译产物与 oracle 逐字节一致。
- 流式指令测试：把同一段回复切成 1/2/3/7 字符三种分片方式输入，解析结果**必须完全相同**。
- 上下文预算：构造 200 轮历史 + 10 万字符世界书，断言不超预算且免责/身份/规则段**永不被裁**。

> 这一阶段结束时**不要写任何 UI**。前身项目的核心教训就是"核心算法散在 UI 文件里，导致无法测试、无法复用、必然分叉"。

### P2 · 数据层
**交付物**（详见 `03-DATA-MODEL.md`）
1. 五层存储落地：结构化 DB / 二进制沙盒（内容寻址）/ 轻量设置 DataStore / 临时状态 / 导出产物。
2. 核心表 + 复合索引 + 外键级联；**禁索引大字段**清单落实。
3. **写入守卫**：`StorageGuard.assertStorable` 挂在**生产仓储实现内部**；`BinaryFree` 标记接口；CI 源码扫描 + 4 个违规 fixture 断言抛错且数据不变。
4. 游标分页仓储 + Paging 3 接入。
5. 迁移：单 schema 声明 + 每版显式 Migration + `MigrationTestHelper` 测试。
6. **备份/恢复（一级功能）**：`BackupRegistry` 驱动导出/清空/导入/容量四处；ZIP + `manifest.json`（dbVersion/appVersion/表行数/校验和）；`ZipOutputStream` 流式写；导入三段式校验（预检未知表硬失败 → 行数与校验和相等 → 提交前 `foreign_key_check` 为空）。
7. 容量统计与**可见报错**（配额/磁盘满必须阻断式 Dialog 并留"最近一次写入失败"记录）。
8. `tools/diagnostics`：7 项自检（索引完整性 / base64 残留 / 孤儿文件 / 悬空引用 / 超大字段 / 慢查询 / 健康分）。

**验收（宪法 §四.2 的红线测试，缺一不可）**
- **性能**：插入 10 万条消息，取第 1 页与第 1000 页 P95 < 50ms；`EXPLAIN QUERY PLAN` 必须出现 `SEARCH ... USING INDEX`，出现 `SCAN` 即失败。
- **守卫**：把 `data:image/png;base64,...` 传给生产仓储 → 抛错且 `COUNT(*)` 前后不变。
- **全表覆盖**：反射枚举所有实体表 ↔ `BackupRegistry` 双向比对，差集非空即 CI 失败。
- **备份往返**：导出 → 清空 → 导入 → 逐表行数与校验和相等；含 1 个媒体文件与 1 本 3 章的书。
- **诊断**：构造"故意漏索引 + 故意留一个 base64"的脏库，诊断能报出 `UNHEALTHY` 并定位到表/行/字段。

### P3 · 原生能力层
**交付物**（详见 `06-NATIVE-ANDROID.md`）
1. `PlatformCapabilities` 全部接口 + Android 实现 + **纯 JVM Fake 实现**（用于单测）。
2. 保活 L0–L4 分层：前台服务（`specialUse`）+ 链式精确闹钟 + 开机自启 + 电池白名单引导 + 状态可视化 + **一键全关（9 项原子释放，`dumpsys` 零残留验收）**。
3. 通知：多渠道 + 富通知 + **通知栏直接回复（RemoteInput）** + 点击定位会话。
4. 精确闹钟（角色能给用户设真闹钟）+ 到点"通知 + 振动 + 原生铃声 + 唤起界面"四件套。
5. Media3 + MediaSession + 音频焦点；「正在播放」读取（**只解析媒体类通知**）。
6. 蓝牙 BLE + SPP；SAF 导入导出；FileProvider 分享；相机/相册；剪贴板；定位/天气；电量/屏幕状态；振动。
7. 本地 ONNX 384 维向量（模型按需下载 + 缺失时优雅降级）。
8. **关键路径**：入站长轮询/推送 → 编译 → 调 LLM → 解析 → 落库 → 通知，全链路在服务侧，**不经 UI**。

**验收**
- **端到端**：真机锁屏 30 分钟，角色主动消息**能收到并自动回复**（这是 E2 的判据）。
- 一键全关后：`dumpsys alarm | grep` 无残留、无前台服务、无 WakeLock、无悬浮窗。
- 断开网络 → 有明确错误分类与重试；恢复网络 → 自动补发未完成请求。
- Fake 实现能让 P4 的 ViewModel 单测全绿（证明抽象层真的可测）。

### P4 · 对话 MVP ★ 产品门面
**交付物**
1. 拟真外壳：状态栏、图标网格（4×N 随主题派生）、Dock、翻页、壁纸、小组件（时钟/照片/横幅/搜索条）、主题皮肤 2 套。
2. **导航注册表**：路由 id + 图标 + 标题 + 是否桌面显示 + 是否 Dock，**一处声明**。
3. **单聊**：`LazyColumn(reverseLayout=true)` + 游标分页；流式打字机（自动滚底、用户上滑暂停 + "回到底部"）；长按菜单（引用/复制/撤回/多选/重新生成/翻译）；消息类型全覆盖（文本/图片/语音含波形/位置/红包/转账/通话/引用/系统灰字）；消息搜索；聊天美化（气泡/头像/挂件）。
4. 角色档案 + 用户面具 + 关系网；世界书管理界面。
5. API 配置界面（四协议 + 每功能绑定独立预设）+ **调试 Trace 面板**（展示本次请求的逐段上下文与 token 占比）。
6. 设置：备份/恢复、容量、诊断、保活开关、通知、外观。

**验收**
- 真机长对话 **5,000 条不掉帧**；内存常驻消息对象 < 100 条。
- 四种协议各跑通一次流式；断网/超时/取消各有一条测试或手工验收记录。
- Trace 面板能回答「模型为什么这么说话」：逐段可见、可临时关闭某段重发对比。
- 拟真度走查：截图给非项目成员看，第一反应是"这是手机截图"。

## 六、Definition of Done（每个任务级）

一个任务算完成，必须同时满足：
1. 代码通过编译、lint、单测；
2. 新逻辑有对应测试（核心算法必须有；UI 至少关键路径）；
3. 涉及数据层的，**表已在 `BackupRegistry` 注册**且迁移测试通过；
4. 涉及平台能力的，Fake 实现同步更新，ViewModel 单测不依赖真机；
5. 文档同步（改了什么、为什么、怎么验证）；
