# 10 · 同类项目对比与差异化（竞品调研）

> 目的：看清同类产品在做什么、我们该学什么、不该学什么、以及**我们凭什么存在**。
> 调研方式：开源项目读其仓库 README 与功能清单；商业 App 读其官方商店页与新闻。
> 标注规则：`[已读源码/文档]` = 有第一手依据；`[商店页]` = 官方描述；`[未查到]` = 没找到可靠信息，不猜。

> ## ⛔ 铁律：只读功能，不抄代码（用户明确要求）
> 1. **不复制、不移植、不"参考实现"任何同类项目的代码。** 本目录下的对比只用于**产品功能层面**的判断（有哪些功能、怎么分类、体验取舍）。
> 2. **不仿冒它们的界面设计。** 可以借鉴"信息结构"（哪些页、哪些入口），**不可**逐像素照抄视觉。
> 3. **许可证风险（必须知道）**：
>    - `float.phone / momo.float.phone` 是 **AGPL-3.0**——**网络服务型传染协议**。一旦复制其代码，我们整个项目（包括服务端）将被迫以 AGPL 开源。**绝对不碰。**
>    - `小手机 / xiaoshouji` 是 MIT，理论上可用，但**仍然不抄**（用户要求 + 抄来会跟我们的架构与视觉不一致，返工更贵）。
>    - EVE 是闭源商业产品，只能看商店页描述。
> 4. **不借用它们的文档格式**：酒馆（SillyTavern）的角色卡/世界书 JSON、float 的预设正则格式、小手机的存储结构——**都不兼容、都不沿用**（DEC-012）。
> 5. 允许学的只有：**功能清单、概念术语（角色卡/世界书/预设这类社区通用语汇）、经验教训**。这些属于思想与方法，不属于代码。

## 一、四个调研对象

### 1. float.phone（AI Virtual Phone / 小手机系列）`[已读源码/文档]`
Next.js Web 应用（可自部署到 Netlify/Vercel，也可 PWA 装到手机桌面）。
来源：[jianchu-in/momo.float.phone](https://github.com/jianchu-in/momo.float.phone)

**功能清单（原文归纳）**
- 仿真聊天：私聊 / 群聊 / 朋友圈 / 语音消息 / 转账红包卡片；AI 角色有**作息、记忆、长期关系**
- 创作系统：角色卡、世界书、预设、正则；桌面 AI 助手「小卷」帮你写这些内容
- 剧情玩法：剧情模式、视觉小说、查手机、访谈、**地图冒险**、日记、便签墙
- 扩展生态：**应用市场（用户用 SDK 写自定义 APP）**、游戏大厅、内置小游戏
- 多媒体：AI 生图、Minimax 语音合成、网易云在线音乐（自配 API）、3D 世界搭建（Tripo）
- 个人云：用户**用自己的 Supabase** 部署云备份、微信助手、离线回复、定时消息、云端来电
- **现实桥**：角色能调用用户的 iPhone 快捷指令，结果回传后继续回复
- **屏幕速聊（iOS）**：辅助触控双击截屏，在系统弹窗里连续对话，并同步回唯一聊天窗口
- 桌面美化：主题、壁纸、贴纸小组件、自定义 CSS
- 所有 LLM 调用用**用户自己的 key**，不内置模型服务

**关键架构事实**
- 纯 Web（Next.js）：**后台能力靠云端 Edge Function 补**（离线回复、定时消息、微信接入、推送）
- 明确写"部分产品设计和系统抽象受 **SillyTavern** 启发，包括预设、正则处理、世界书/lorebook/WorldInfo 等概念"
- 许可证 AGPL-3.0（注意：与我们无关联，但其"世界书/角色卡文档格式"已是社区通用语汇）

### 2. 小手机（本地化沉浸式 AI 聊天 PWA）`[已读源码/文档]`
Vue 3 PWA，纯前端本地应用，数据默认存浏览器 IndexedDB，无后端账号。
来源：[Guaizai-s/xiaoshouji](https://github.com/Guaizai-s/xiaoshouji)（另有 [Guaizai-s/small-cloud](https://github.com/Guaizai-s/small-cloud)）

**功能清单（原文归纳）**
- 仿微信聊天 + 短信风格聊天两套界面；通讯录、角色详情等手机应用结构
- 多 AI 角色管理：头像、设定、系统提示词、聊天背景、**每个角色可绑定独立 API 方案**、上下文轮数
- API：OpenAI 兼容 + **Anthropic 格式**，自定义 Base URL / 模型名 / Key，流式开关，**超时与简单重试**
- 多媒体与特殊消息：图片发送与图片识别、MiniMax TTS 语音、表情包系统并与角色库绑定
- **指令格式**（原文）：`[语音:文本]` `[表情:表情名]` `[红包:金额:备注]` `[转账:金额:备注]`
  并明确原则：**"模型只负责输出固定格式，真正的执行、扣款、语音生成和渲染由前端代码控制"**
- 本地钱包：用户与每个角色独立余额、余额不足阻止交易、流水落库、**金额用「分」整数存储避免浮点误差**、删消息不回滚账务
- 时间感知与记忆：当前时间与消息时间感知、角色核心设定与长期记忆、用户人设卡与用户状态
- 本地存储：roles / conversations / messages / apiProfiles / userPersonas / stickers / assets / walletAccounts / walletTransactions
- 备份导出导入，**旧版本备份缺新表时按空表兼容**
- 提示词分层（原文列举）：基础系统规则 / 时间感知 / 角色原始设定 / 核心设定 / 长期记忆 / 用户信息 / 用户状态 / 特殊消息格式 / 可用表情包列表 / 最近聊天上下文
- 开发原则（原文）："每次只改一个明确问题""特殊格式统一走 parser/directives""不要把 API、数据库、主题、语音逻辑混在一次改动里"
- 路线图：世界书/预设/Style 规则、记忆库搜索、自定义 CSS、日记、阅读、小账本、语音通话、Web Push、轻量后端代理

## 三、我们该学什么（直接采纳）

| 学什么 | 从哪来 | 为什么 |
| :--- | :--- | :--- |
| **指令协议 = 模型输出固定格式，执行权全在客户端** | 小手机原文 + 前身实践 | 这是本类的通用做法，也是安全边界（模型不能直接扣钱/发文件） |
| **多协议：OpenAI 兼容 + Anthropic + Gemini** | 小手机（前二）+ 前身 UI（写了四种但是死字段） | 用户自带 key，渠道五花八门；这是刚需不是加分 |
| **每个角色可绑定独立 API 方案** | 小手机 | 用户常按角色分渠道/分模型 |
| **金额用「分」整数存储** | 小手机明确提到 | 浮点误差 + 幂等是账务两条命 |
| **删除消息不回滚账务** | 小手机 | 账务与消息是两个事实源，不能互相污染 |
| **备份缺新表按空表兼容** | 小手机 | 与前身"备份漏 44/87 张表"是同一课 |
| **提示词分层清单** | 小手机列出的 10 类 | 与前身的 depth 拓扑互相印证，说明这套分层是行业共识 |
| **"每次只改一个明确问题"** | 小手机开发原则 | 与我们的"每轮一个小模块"一致 |
| 角色卡 / 世界书 / 预设 / 正则 这四个概念 | float.phone + 社区 | 用户心智已建立，**概念要支持，格式自己定**（宪法：不做酒馆兼容） |
| 角色有**作息** | float.phone | 让"角色在过自己的生活"更可信，成本低收益高 |

## 四、我们该躲什么（前车之鉴）

| 别学 | 原因 |
| :--- | :--- |
| **抄任何同类的代码** | 见文首铁律。float.phone 是 AGPL-3.0，抄了我们就被迫开源；其余抄了架构与视觉都会打架，返工更贵 |
| **用云端 Edge Function 补后台** | float.phone 因为纯 Web 只能这么救；我们要的是**设备本地就能收能回**，不依赖用户自建 Supabase |
| **把"离线回复"做成第二套提示词** | 前身的血泪：原生快照 + 网页拼装 = 两套 system prompt 必然分叉。我们必须**同一份编译器** |
| **依赖第三方公共 API 做核心功能** | 前身用了 `api.i-meto.com`、allorigins 公共代理、网易云直链——任一失效即功能残废。要么用户自配，要么不做 |
| **把用户数据塞进别人的托管库** | float.phone 要用户自建 Supabase；我们的数据默认在本机（Android 私有目录 / 浏览器 OPFS） |
| **用 emoji 当图标** | 用户明确否决；且 emoji 在不同系统渲染不一致，毁拟真感 |
| **格式兼容当卖点** | 用户明确否决（不做酒馆兼容）。兼容是短期拉新，长期是给自己上枷锁 |

## 五、我们凭什么存在（差异化三条，含"同类做不到"论证）

1. **后台真的活着（同类做不到）**
   float.phone 与 小手机都是 Web/PWA：浏览器被冻结就无法自主收信，float 只能靠用户自建云端补，小手机完全没有。
   我们用 Android 前台服务 + 链式精确闹钟 + 原生长轮询，**关掉 App、锁屏、UI 被杀之后角色仍能收到并能自动回**，且**不依赖任何第三方云**。

2. **真机系统权限（同类做不到）**
   通知栏直接回复、写系统闹钟、悬浮桌宠、蓝牙、本地媒体控制、ONNX 本地向量检索。Web 沙箱里这些物理上不存在。

3. **数据永不撑爆 + 模块可持续追加（同类没解）**
   前身 87 张表、备份漏一半、base64 入库导致导出 40MB 崩溃；同类项目也没给出数据规模治理方案。
   我们把"二进制外置 / 游标分页 / 备份注册表驱动 / 容量可见报错"写成**可执行的测试红线**，并且用模块边界保证"以后加 20 个应用不用动地基"。

> 一句话：**别人做的是"网页里的假手机"，我们做的是"手机里真的住着角色"。**

## 六、对我们产品设计的直接影响（落地到文档）

1. **API 设置**：四协议（OpenAI 兼容 / Anthropic / Gemini / 自定义）+ 多套预设 + 按角色与按功能绑定 + 拉模型列表 + 测试连接（真实报错）。→ 已写入 `01-PRODUCT-AND-STACK.md`，第 1 步优先做。
2. **指令协议**：保留方括号字面格式（宪法 §六），内部收敛为统一 `DirectiveRegistry` + 流式增量状态机。同类印证了"固定格式 + 客户端执行"是正确的。
3. **账务**：整数分 + 事务 + 幂等键 + 独立于消息。
4. **提示词分层**：与我们 `07-AI-ENGINE.md` 的 depth 拓扑合并对照一次，确认无遗漏（小手机那 10 类是我们的子集）。
5. **可考虑借鉴的玩法**（不承诺、列为候选）：角色作息、日记、便签墙、访谈、地图冒险、查手机（前身已有）。
6. **明确不做**：酒馆格式兼容、云端 Edge Function 补后台、依赖公共第三方 API 做核心功能。
